## Summary
The unit holds the pure rules of time (`clock.rs`: cron, POSIX zone rules, phrases like "tomorrow 9am"), the routine and reminder tick (`routines.rs`), swarms (`swarm.rs`), the Pebble ring's notes (`ring.rs`), the uberbot's op log (`uber.rs`), rooms shared between the owner's machines (`far.rs`, `mesh.rs`), the one-time move of bot folders (`relocate.rs`) and the told and task-board tools (`ledger.rs`; it is not a token or cost ledger, the unit prompt's "price table" does not exist). The pure code is careful and well tested: saturating arithmetic, a bounded cron scan, zone transitions checked against a recorded corpus, one catch-up run per routine after downtime, and nothing fired on a copy hub by the tick. The risks are where the bots' world lock, the log and other lanes meet. A swarm claim takes agent locks while the world lock is held, and a lock grant takes the world lock while the agents' work lock is held: the two orders can deadlock the bots lane. The ring's "the person's own words" trust is given to any webhook that sends a ring-shaped form, not only to the ring's hook. Routine firing is at most once with the delivery error thrown away, a deleted bot's routines keep firing into the log, and a routine in a zone the hub has no rule for is accepted and never fires because the zone resolver the docs describe was not ported. Swarms have no ceiling on nesting or count, and neither the budget nor Stop interrupts a running member. Shared rooms lose posts made while the other machine is away. The reviewer of unit 39 asked whether an unsigned ring delivery can take a real note's id: only a caller that already passed the hook's authentication can, see the Low finding on ring.rs:62.

- A multipart form with `client=ring` on a webhook that is not the ring's: it must arrive as webhook data, not as a spoken message.
- `tick_at` after `bots.delete`: no `RoutineFired` for the deleted bot's routines.
- A routine whose delivery fails (an inbox that returns `Err`): it stays pending or is retried, and a one-time routine is not done.
- `routine_set` and `bots.routine` with a zone that has no rule: refused or resolved, and a `zone.report` of an unknown zone does not stop the person's routines.
- `Cron::text("every 45 minutes")` and "every 7 hours": refused, or even gaps.
- A machine-zone (`tz: ""`) daily routine across the end of daylight saving with `tz.machine` holding a DST rule: one run that day.
- An edit of a schedule to a time of day already past: no run at the next tick.
- `ledger::same` and `push::repeat` with Japanese texts that share one ASCII word: not a repeat.
- `swarm_create` called by a swarm member; a budget above the cap; `stop` while a member's turn runs.
- `far_forward` with the link down for a post, then up: the post arrives; a member leaving after a restart reaches the other machine.
- `move_bot` run twice after a failure part way: one backup, no overwrite of a file changed in the new folder, symbolic links kept.
- A bearer delivery and a later signed delivery with the same `X-Index-Delivery` and different audio: both kept.
- `ring_recover` on a copy hub and in safe mode: nothing heard or sent.
- `when_parse("in 99999999999999999999d")`: `now + s` at clock.rs:322 overflows (a panic in a build with overflow checks, a wrapped value that the final filter drops in release); use `checked_add` and refuse times more than a few years ahead.

## Style nitpicks
- swarm.rs:403 `let _ = HashSet::<()>::new;`, `batch_note`'s unused `names` (swarm.rs:70) and `far_membership`'s unused `w` (far.rs:209) are leftovers.
- `plan_of` is written three times (routines.rs:52, sched_text.rs:40, clock.rs tests) and `gs` in every file.
- Two machine identities with similar names: the setting `machine.id` (uber ops) and the file `<home>/machine-id` (mesh); `my_mid` writes its file without an atomic rename and ignores the error (mesh.rs:73).
- Three functions give "the hub's address for webhooks" with different rules: hooks.rs:30 (no `tailscale serve`), ring.rs:41 and `front::base`; `bots.hook_token` can show an `http://` listen address where the Ring page shows the HTTPS one.
- `Zones::valid` (clock.rs:342, ASCII) and `settings::zone::valid` (Unicode letters) differ.
- ring.rs keeps `HEAR`, `BUSY`, `QUERY` and `TEST` as process statics, not per hub; `mesh_watch` holds a strong `Arc<Bots>` in a loop that never ends.
- `stamp_next` (uber.rs:15) formats the counter with six digits and reads back six: past 999,999 ops in one second-stamp the order breaks.
- `uber_heal` (uber.rs:149) drops the world guard before it commits ops numbered under it.
- Many doc comments name the removed JS tree's functions (`Bots.tick.state`, `Cron.raw`, `Ub.fires`) as the specification.
- The unit prompt describes ledger.rs as token and cost accounting; it is the told ledger and the task board.
