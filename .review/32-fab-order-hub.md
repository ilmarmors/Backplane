## Summary
The unit has two halves. `fab/` keeps per-fab capability profiles (bundled baselines, a daily gather of the fabs' pages through curl, a per-project choice), turns them into a marked section of the project's `.kicad_dru`, proposes stackups with impedance widths, and publishes the Fab panel. `settings/fab.rs`, `order.rs` and `order_view.rs` are the Buy flow: the project card and its price estimate, the review gate, the files' approval, the upload, the quote poll and the order watcher. The code is careful where it was designed to be: curl URLs and headers never reach a command line, the order server address is validated, the upload is pinned to the manifest the person saw, the pay token stays out of the log, the server's markdown is sanitised, and a copy hub cannot send. No path lets an agent pay or upload without the person's Send, and the hub does no price arithmetic (totals are the server's strings). The main risks are elsewhere: the built-in order server is a bare IP address whose only identity is an IP certificate; the stored profile always beats a newer bundled baseline, so corrected values never reach a home that gathers and a false "stale" note becomes permanent after 120 days; the Fab panel of a second board acts on the first board's project; inner-layer impedance widths use the centred stripline formula on offset stackups and are about twice too wide; and the order flow has three exits that leave a thread waiting or a record in `quoting` for good. Tests are dense for pure functions and thin for the failure exits of the order flow and for profile upgrades.
