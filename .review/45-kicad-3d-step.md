## Summary
The unit turns a .kicad_pcb into a layered 3D board in-process (parse, i_overlay booleans, triangulation, a GLB and the varint "solid" wire frame), resolves each footprint's 3D model reference to a file, converts STEP/WRL models to GLB (the native OpenCascade helper `backplane-step2glb`, FreeCAD as fallback, VRML read natively) into a content-keyed cache, and streams parts to the clients. The code is careful in many places: the GLB reader caps triangles, JSON depth and node walks; the sexpr parser caps depth; numbers from the board are forced finite; every converter output goes through a private stage folder and one rename; helpers are started without a shell through `proc.rs`; the wire encoder and the GPUI decoder agree (zigzag of wrapping i32 deltas, at least 10 bytes a triangle, 5-byte varint limit). The main risks are inputs that are cheap to write and expensive to read, run inside the hub process with no memory bound: a VRML file's DEF/USE is expanded by deep copy (exponential), and a board's embedded zstd model is decompressed with no size limit; either kills the hub when a board from an untrusted repository is merely opened (the prewarm runs on open). Model paths go unescaped into FreeCAD's tab/newline job file. Caches are keyed by content only and are never pruned, so a FreeCAD-made or old-detail mesh stays forever and per-revision/per-zoom meshes accumulate. kicad-cli is run with no timeout while holding the one-3D-model lock. Tests cover the happy paths and a few malformed GLB/JSON cases, but none of the hostile-input cases above.

## Missing tests
- A VRML with nested DEF/USE doubling (must fail or stay bounded in memory and time).
- A board whose embedded file is a zstd frame that expands past a limit (must be skipped).
- A model path containing a tab and a newline through `freecad()` with a stand-in FreeCAD (no job file corruption, other jobs still convert).
- A STEP whose path holds `\nPART 1 1 /x.glb` through `step2glb_run` with a stand-in (no forged event).
- A kicad-cli stand-in that never exits (export must time out and release the 3D lock).
- A GLB with many primitives over one large accessor and zero-count indices, and an unaligned accessor with a huge count over a tiny BIN (bounded time and memory).
- `gr_text` on Edge.Cuts with an "O" (outline unchanged).
- A cache hit made by FreeCAD when step2glb is available (expect a re-mesh or a key that differs).
- Parser fuzz: random truncations and byte flips of the fixture boards through `parse::board` and `mesh::layers` (no panic, bounded time).

## Style nitpicks
- `stream::encode_model` negates `q(y)` (stream.rs:136); `q` saturates to `i32::MIN` beyond 21 km, and `-i32::MIN` panics in debug/test builds (wraps in release).
- parse.rs:358 `let s = if ... && false { s } else { s };` is dead code.
- parse.rs:203 `pad_layers` takes `ty` and discards it.
- models.rs:851 `let _ = (&mut ok, &mut bad);` in the bench is noise.
- glbw.rs:63 and 80 write `l.name` into JSON unescaped (fine today because names are `&'static str` constants; fragile if a name ever comes from data).
- `stepglb::fnv` (32-bit) and `plot::mesh_id` (FNV-64) name cache files (`board-native-v2-<fnv(path)>`, `embedded-v1-<mesh_id>`, `board-solid-v2-<mesh_id>-<len>`); collisions are unlikely but would quietly show another board's or another file's model; sha256 is already at hand in models.rs.
