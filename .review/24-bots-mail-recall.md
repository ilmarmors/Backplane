## Summary
The unit is the bots' mailroom and the bots' memory tree. Mail is a body in a per-conversation journal (`<home>/mail/*.jsonl`) plus header events; a filed header is routed to a "run" (a thread of its own that works one conversation for a bot), and for the uberbot to a triage run, a private back office and a done digest; `recall/` keeps a binary tree of one-line summaries so a bot's thread can start every turn in a fresh session. The code is dense but well organised: decisions are pure functions over a `Ctx` that return a `Step`, the journal refuses links and repairs a torn tail, the owner exchange between machines is signed and idempotent, and the tests are substantial (triage, owner, recall). The main risk is the charter gate: a run's permission prompts are answered "allow" unless a substring deny-list matches, and that list misses file-writing tools, most destructive commands, `terminal_send` and the persistence tools, while runs read text from other agents, webhooks and other machines' bots. The second risk is state that only grows or never clears: a stopped triage run holds its conversation for good, thread-end mail leaves a ticket nothing claims, the walker re-routes the same sixteen tickets every 20 seconds, and per-mail settings, runs and headers are never pruned. Third, several answers are given before the commit, so a tool reports success when nothing was written. Sender identity is re-derived from the first 160 characters of the text with the mailroom on, which a sending thread controls. Note that `mail.on` has no switch in any client and no client calls the `mail.*` requests: the live path today is the uberbot's triage with the mailroom off; findings that need `mail.on` say so. `recall/` is off by default; its tree logic is sound, its engine reads the whole backlog on the runtime at each turn while the compactor is behind.

- A `triage-end:` mail leaves no pending ticket; with more than 16 pending tickets every one is walked; the walk appends no event when nothing changed (a queued input behind a live run, a held conversation).
- A queued id with no header is dropped and the next input starts; the uberbot in a direct room with the mailroom off triages a second message.
- `mail` with a `conv` the caller is not part of is refused; `mail` to an unknown target is an error; `mail_snooze` with no time is refused.
- A `thread_send` whose text starts with `[routine: x]`, `[webhook: x]` or "Backplane restarted" is filed as the thread's.
- `escalate(to: "person")` from a managed bot's run reaches the coordinator and is not marked told otherwise.
- `decide_with` on a failed commit: `tell_person`, `mail_dispose` and `escalate` answer the failure.
- A brief whose delivery fails ends the run as failed and lets the queue go on.
- Journal: a last line longer than several 64 KB chunks; a `Malformed` tail; a conversation id longer than 255 bytes encoded; two ids that differ in case; the torn-tail repair on Windows.
- An imported `triage-end` owner mail starts no run on the holder; a ticket whose recipient is no longer linked is planned again.
- Recall: a failed `RecallNoted` commit holds the thread; `Kept::noted` and `viewed` ignore out-of-range numbers; `view` over a backlog reads only the lines it shows.
