## Summary
This unit is the hub's start-up (`main.rs`), its hand-rolled HTTP server and WebSocket loops (`wire/`), the credential rules (`auth.rs`), the CBOR dictionaries and eight small helper programs. The authentication core is sound: every route is refused without a credential unless its handler opts out, the token compares are constant time over equal lengths, a cross-site Origin is refused, the WebSocket and CBOR decoder are bounded (512 KiB, depth 64, 50,000 nodes), and a revoke closes live sockets with a tested attach-then-admit order. The hub and client dictionaries hold the same 50 keys and 61 words in the same order (they differ only in `i18n-ok` comments), but nothing checks that. The largest risk is in start-up: `copy::mark` runs on a copy too, so one guarded run makes a copied home pass the copy gate without the switch from then on. The edge handles sockets before authentication loosely: no timeout before the first request byte, no connection cap on the main and tailnet listeners, and a `hostname` process started for every unauthenticated `GET /`. When the device registry refuses its file, `Auth` falls back to a snapshot that ignores the file's owner, so old devices keep signing in and cannot be revoked. The home and the event log are created with default permissions, so other local users can read the log. Secondary listeners (tailnet, LAN) serve the hub before start-up has finished, and the socket loops answer requests inline, which stops heartbeats during a slow request. The unit also carries dead code from the removed helper process and two copies of the auth rules.

## Missing tests
- A start with `BACKPLANE_COPY=1` on an unmarked, real-looking home leaves no `hub.owner`, and the same home is refused afterwards without the switch.
- A second hub started on a served home changes nothing under `<home>/guard/` and exits with the "already serves" code.
- A connection that sends nothing, and one that sends half a head, is closed within the deadline (no such deadline exists today).
- A head over 16 KB and a head with more than 64 header lines get 400; a WebSocket message over 512 KiB ends the connection.
- `Auth::load` with a `devices-v1.json` whose `owner` is not the token's hash, and with `version` other than 1: no device credential is admitted.
- Hub and client `wire_dict.rs` hold the same entries in the same order, and today's entries keep their positions.
- `ensure_token` on a home that holds an empty `token` file.
- A plain-stream join while text streams: the text a client builds from `live` plus the following `delta` frames equals the hub's live text.
- A request that takes longer than the client's 35 s heartbeat limit: the socket still sends `hb`, and a revoke during it closes the socket.
- Mixed credentials: an empty `Authorization: Bearer ` with `?token=<root>`; a wrong bearer with a valid cookie; `Sec-Fetch-Site: same-site` with a cookie.
- `GET /` many times does not start a process per request.
- A client that connects through a secondary listener before the start is over gets the "starting" answer.
- `bp-sh` on Windows with a real `sh -c`: an argument that begins with a drive path and contains quotes or doubled backslashes, an empty argument, and a non-ASCII argument arrive unchanged (today only the string `quote` produces is tested).
