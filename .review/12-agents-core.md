## Summary
The unit is the thread actor (one task per thread, a mailbox of 64, one agent process), the process layer under it, thread_launch with its reports, and the small pure rules. The process layer is careful: stand-ins are resolved strictly inside the stand-in folder, queues are bounded, lines are capped at 32 MiB and read lossily, stderr is drained by its own task, every child is reaped, and no hub token is put in an agent's environment. The turn machine is where the risk is: `mod.rs` is 146 KB with a 40-field `Actor`, and each way a turn starts or ends repeats its own subset of the bookkeeping (which fields are reset, whether the end is marked, whether the checkpoint runs), so the paths have drifted apart. The Stuck watchdog reads a command ledger that can belong to an earlier process and ends live turns (most likely right after the default Claude to Codex failover); the account retry only works for turns started by `user`; `user` starts turns in deleted threads; the first four carried threads are not re-judged after a restart. An enforced standing rule with an unlock word can be unlocked by the governed agent itself, because any role "user" message counts as the person's. One statement in `spawn` holds the hub-wide world mutex across a `git worktree add`. A failed commit is logged and ignored, so the agent runs on a message the log does not hold. There is no cap on launched threads or agent processes, and an idle Claude process is kept for every thread until a manual settle. The copy gate is checked at every start; its only defect is that the person's own steer of a non-Claude turn is refused. Tests cover the ordinary paths well (about 150 async test functions in `agents/tests.rs` and `agents/tests/`) but mostly run a stand-in that reports no CLI version (the ledger stays in legacy mode) and never set `BACKPLANE_STUCK_S`: the Stuck path in the actor, the reuse of one actor across providers and the account retry of starts other than `user` are untested.
