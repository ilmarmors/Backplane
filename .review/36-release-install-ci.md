## Summary
The unit is the way a build reaches people: nine workflows, the `curl | sh` installer, the 0.14 hand-over scripts, and the build and gate scripts. The installer and the hub's update check are careful: archives are sha256-checked, a build is made by one rename, the manifest's tag, version and channel are bound to the release, and a release is a draft until its signed files are up. The weak part is everything before the signature. The job that builds the signed archives runs third-party actions by mutable ref, the signing key is a plain repository secret that every dry run also uses, and a pushed `v*` tag on any commit is built, signed and published with no test, no smoke and no check of the tag. CI's path filters leave out files the crates compile in or test, so many changes run no test at all. Answers to the lead's questions: (a) no CI job builds the hub with `e2e-trust` and none runs `test/update/feed.sh` or `test/guard/faults.sh` (they are run by hand; the guard's unit tests run only when `native/guard/**` changes); (b) yes, `main-build.sh` sets `MAIN_PREV`, so `dev-build.sh:45` runs `build-haiku.sh` and one `claude -p` call on every build of main, on the default login and then on the live hub's named accounts, documented in docs/MAIN-BUILD.md but with no switch and no per-build go; (c) confirmed, `scripts/boat-base.sh:15` pipes an unpinned installer into bash, and its sccache and Rust are unverified too. Several deploy files (`deploy/windows`, `deploy/aur`, `backplane-launch.sh`, `backplane.desktop`, `kicad-library.lock.json`) belong to the removed tree and nothing uses them.
