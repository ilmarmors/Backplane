## Summary
The unit holds the plot actor behind `kicad.watch` (`watch.rs`), the managed install of the KiCad fork (`install.rs`), the rules for design files on main (`canonical.rs`), and small pure modules (project files, boards list, check and release templates, export paths, management panels, KiCad progress). `install.rs` is the strongest part: the archive is pinned by a SHA-256 in the binary, member names, links and the manifest are checked, nothing privileged runs, and the tests cover the fetch, the zip reader, the lock and resuming. `watch.rs` reads every board, schematic, Gerber set and 3D model inside the hub process with no size or file-type check and no time limit, so one hostile or huge file can end the hub; `catch_unwind` covers only panics. Plot frames go to the socket outbox with no pacing, and the outbox answers an overflow by removing the client, so a large cached model disconnects whoever opens it. A failed read leaves the older plot under the newer stamp, so a later viewer is shown a stale drawing as current. `canonical.rs` has one serious logic gap: bringing an older worktree's design files back compares bytes only, so a worktree that is merely behind overwrites main's newer boards. The folder check of `kicad.watch` (`mod.rs` `allowed`) skips relative parts of a version path and never looks at `tree`. Several things grow without bound over a long uptime: info files under `<home>/plot`, per-project info keys (against a hub-wide cap of 256), and KiCad progress jobs that are never cleared and then defer every ERC and DRC run. Blocking directory walks (`project::read`) run on async threads in several hot paths.

## Style nitpicks
- Comments still name the removed tree as the specification ("server/plot's actor", "Pv.*", "core/release in Rust", "Law boards_list_offered", "Pure twin of rule until the rules process is wired").
- Source kinds are bare numbers (0 to 4) and are tested by key prefix (`ky.starts_with("2|")`) in some places and by `solid_kind` in others.
- Keys are joined with `|` and split again (`family`, session/pages.rs:180); a project folder with `|` in its name splits wrongly.
- Info files are named by a 32-bit FNV of the key; two live keys with the same hash would share one file.
- `gc` orders idle sources by "was idle before", not by age; the comment says the older go first.
- `mgmt::store` writes one fixed `panels.json.tmp` outside its lock; two saves at once can mix.
- `canonical::is_doc_lock` matches any lock named `kicad-…-pcb-…`, including one a person named so.
- `commit_design` passes file names as pathspecs; a name starting with `:` is read as pathspec magic (`GIT_LITERAL_PATHSPECS=1`).
- `.kicad_prl` (per-user view state KiCad rewrites on open) is a design file, so a turn can commit and push it alone.
- `release::valid` lets `a.lock/b` through, which git refuses.
- `boards::find` goes five levels deep and `project::found` four.
- `focus_box` takes any positive finite radius; a huge one gives a box of NaN.
- `links_inside` resolves targets lexically; a link through another link can leave the runtime (only matters if the pinned archive is hostile).
