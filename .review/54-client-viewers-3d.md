## Summary
The unit is the desktop 3D and Mech viewer: a hand-written CBOR reader and mesh decoder for the hub's `solid` frame, a worker thread that decodes and draws (GPU through blade on Linux, a tiled software rasterizer everywhere else), a free-orbit camera, picking, part fade-in, plus the Boards menu, the layer masks helper and a `--solid-demo` measurement mode. The wire code agrees with the hub's encoder (colour XOR, zigzag deltas of 10 um, `at` as 12 little-endian f32, `faces` runs, the (64<<20)/84 triangle ceiling), and the decoder checks counts, lengths, depth and non-finite placements before allocating, so a malformed frame returns an error rather than panicking in the decode path. The rasterizer and shader are careful (exact integer edge functions, near-plane clipping, two-sided lighting, one sRGB transfer). The main risks are state handling around the worker, not the maths: a "Building" stage that is never cleared when a large frame fails to parse, a restored model that can ignore the hub's newer stream, one GPU hiccup that switches the whole process to the CPU path for good, and a worker thread whose death freezes the page with no message. macOS and Windows have no GPU path at all. Repaint is bounded (timer only while a stage runs, fade renders chain only while fading). Test coverage is wide on the happy paths and on camera maths; malformed-frame, GPU-failure and stale-state paths are not covered.

## Missing tests
- Malformed or truncated frames of every kind (`parse_frame` on truncated CBOR, a map over 256 entries, bad UTF-8 key, a 1M-element `refs`), asserting None or `Bad` and no panic, plus the worker: a frame over `BUILDING_BYTES` that fails to parse must clear the stage (finding 1).
- A six-byte varint, and a fifth byte above 0x0f, must be rejected by `Varints`.
- `Scene::take` order cases: Part before Model, Parts for another key while a board is held, Note for another key, `done > of`.
- The restored path: `want()` back to a kept model, then a `Model` frame with fewer parts and `of == 0`; assert the new board is applied.
- `decode_part_faces` with finite but overflowing matrices; `Camera::zoom_by` and `fit_to` with a NaN centre must not panic.
- GPU fallback: a forced `render_layers` failure (feature-gated stub) leaves later pictures drawing on the CPU, and a transient failure recovers if the back-off is added.
- `lit_layers` with a `refs` list whose length does not divide the triangle count (it divides by `m.refs.len()`).
- Boards menu: a press on the button while open closes the menu (finding on `on_mouse_down_out`); `editor_follows` with an empty `all`.
- `layers::plan` with a layer id equal to `NO_LIFT` (255) is treated as lifted; assert the intended behaviour.

## Style nitpicks
- Very long lines (the `SolidPage` struct fields and `render` run to 300+ characters per line, with doc comments inside the struct body); long `/* i18n-ok */` markers inside expressions make the code hard to read.
- `solid.rs:131-135`: a doc comment for `combine` is attached to `append` (two doc blocks in a row).
- `Fx::write_i32` is dead for the keys it hashes; `smooth_normals` (the wrapper) has no non-test caller.
- `lit_color` mixes towards `0xffe066` (an sRGB-looking constant) in linear colour space; fine visually but undocumented.
- `put`/`zig` helpers are duplicated in demo.rs and the tests of solid.rs.
- `Mesh` derives `PartialEq` on 60 MB of vectors; nothing seems to need it except tests.
- `layers.rs` `NO_LIFT = 255` is also a valid layer id value in `plan`; use `Option<u32>`.
