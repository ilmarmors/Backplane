## Summary
The unit is the pure presenter side of Settings (22 pages), the first-run setup (five steps plus Done) and the "Sign in there" panel. Each page is a function of state, drafts and hub info that returns `{label, note, fields, buttons}` rows, and each press returns a session patch plus hub requests. Secrets are handled well: API-key and sign-in boxes are `vault` fields that never become drafts, key names only are listed, and the webhook secret is a path. The code is dense but coherent, with many tests on row content. The main risks are in the glue between the rows and the actions. The desktop's typed text is dropped by a `bfield` whitelist that misses four Voice and Ring fields, macOS gets the wrong Git command because `"macos"` is compared with the hub's `"darwin"`, and step 4's "done" contract contradicts its own comments. A fair amount of dead code and two stale docs (`docs/settings.md` describes a web client that no longer exists, `docs/onboarding.md` is out of step with the code on telemetry and Windows). Validation before `setting.set` is mostly left to the hub, and `setting.set` itself accepts any key except a few reserved ones.

## Missing tests
- For every page, every `fields[].name` in `rows_of` output must be accepted by `act(..., "bfield", "<name>\u{1f}x")` and then read back by the row (would have caught the Voice/Ring bug).
- `git_fix` with the hub's real `os` values (`darwin`, `windows`, `linux`), not `macos`.
- Step 4: Boat chosen, no Boat made, Next, then the Done page lists the step (or the test that documents it does not).
- `end` / `ob-end` on a home whose `onboard.seen` lacks `welcome`: the telemetry notice is not "setup".
- `step4_press` while Settings, Machines is open on a blank home.
- `loopback()` with `http://localhost.evil.example` and `http://127.evil.example` (or delete the function).
- `ob-project` with `~/x`, a UNC path `\\srv\share\x`, and `a:b` (the `chars().nth(1) == ':'` check accepts any second-character colon).
- Settings Devices: a device with `revoked` true is hidden, one with `revoked` as the string "true" is hidden, and a revoke of the last open invitation.
- Webhook: `hook-url` with 2001 characters and with a control character.

## Style nitpicks
- Several lines exceed 400 characters (one-line functions with whole match bodies); the Settings `act` match is ~120 lines of one-liners.
- `set`, `s`, `draft`, `btn`, `row` are re-defined in settings.rs, onboard.rs and signin_there.rs (same bodies).
- `let _ = st;` and `let _ = session;` in `about`, `keys`, `send` instead of removing the parameters.
- `let r = yourself(...); r` in `kicad_row` (needless binding).
- `"Skip FreeCAD if you only design boards"` body vs Next reading "Skip step" until both tools are found.
- Agents step is done when any of Antigravity, Grok, Muse, OpenCode, Pi or Oh My Pi is merely found, but Claude or Codex found and not connected is not done.
