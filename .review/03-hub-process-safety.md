## Summary
The unit is the hub's safety floor: `proc.rs` gates every child process by a `Kind`, `copy.rs` holds the copy switch and the gate on a home, `guard.rs` writes the state files the guard reads and serves `/healthz` and `/hub/control`, `memscope.rs` puts agents in systemd scopes, and `plat/` hides the Unix and Windows differences. The design is sound and well tested where it is pure: the rule per kind, the scrub of the guard's variables, the request file made with a hard link, the size validation of systemd arguments and the Windows lock on a far byte are all careful. The weak point is that several guarantees are stated more strongly than the code holds them. Gate 1 (the home) is defeated by its own marker: a copy run with `BACKPLANE_COPY=1` writes `hub.owner`, so the next start without the switch is no longer refused, and a home copied whole brings the marker with it. The source scan that is said to fail the build on any `Command::new` or socket outside `proc.rs` stops reading each file at its first `#[cfg(test)]` line, so it never sees most of `agents/mod.rs`, `hub.rs` and a dozen other files; one raw `Command::new("git")` that writes to the project repository has lived in that blind zone since 2026-11-06. A refused spawn reaches callers as "No such file or directory", so safe mode and the copy guard both tell the person the agent CLI is missing. The environment scrub is by `Kind`, and commands a project supplies (`checks.json`, git hooks) run as `Local` and keep the hub's variables. On the guard side a start step that runs past its budget is reported lost but keeps running detached. Windows process groups are the least proven part: a Job Object whose only handle is closed cannot be found again by name, so the group kill and the memory cap for jobs that outlive the hub most likely act on the leader only. `copy.rs` still carries the JS hub's `out_fate` family, used by nothing but its own tests, under a header that says the hub asks it.
