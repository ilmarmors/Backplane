## Summary
The unit is `backplane-voice`, the hub's child process for speech to text: `live` (microphone or stdin to words, by OpenAI's realtime session or by sherpa-onnx on this machine), `file` (a recording), `serve` (one recognizer kept loaded behind a Unix socket), `record`, `devices` and the `local-*` install commands, with NDJSON on stdout as the contract. The code is careful where it matters most: the key is read from a file and appears only in the Authorization header, TLS uses the Mozilla roots with no off switch, every download lands in a staging folder, is fsynced and checked against a pinned hash before a rename, the tar is unpacked in-process with climbing paths refused, the hand-written C structs are compared with the header by two tests, and the library's version is checked before anything else in it is called. Audio buffers from the recorder are bounded, a panic ends with `error` and `end`, and the event names match what the hub's reader parses. The main risk is always-on with the cloud engine: `--always` only removes the time limit, so the per-press cloud path runs without end and uploads every sound above an energy threshold to OpenAI before the hub decides that a message started; the helper should refuse the combination. Second, every failure is the same `error` line and exit code 1, so the hub cannot tell a revoked key or a missing recorder from a network blip. Third, three places have no bound or time limit: model downloads (no read timeout), ffmpeg's decoded output, and the realtime socket (no keep-alive, an unbounded send queue, and lost last words reported only on a stderr the hub discards). The energy segmenter of the cloud path latches open in steady noise. Tests are good for the per-press paths and the installer; `--always`, a socket closed mid-session and the resident socket protocol have none that run without the downloaded model.

## Missing tests
- `live --always` with the OpenAI engine: refused with a permanent error (or, until then, a test that pins what is sent).
- A realtime socket closed by the server mid-session: `error` "the connection to OpenAI closed", then `stopping`, `end`, exit 1.
- The class of each failure once errors carry one: 401, 403, 429, no key, no recorder, model missing, a recorder that dies, a refused connection.
- `Segmenter` with steady noise above the level, and speech on top of it: segments must still end at pauses.
- `--always`: no `silent` hint in a quiet start, and no stop after the 10-minute limit (tokio's paused clock).
- A stop when no transcript comes within 8 s: an `error` event and a non-zero exit, not a silent exit 0.
- The resident protocol with a stand-in decoder: a hello for another model, a count over `MAX_SAMPLES`, turn and voice frames, the server gone mid-session, a late answer after a timeout not taken for the next one.
- Install: a server that sends half a file and then holds the connection; two installers in one folder; an archive with extra files or a link in the model folder; an archive larger than a cap.
- `file`: ffmpeg output past a cap; the 90 s limit ends with `error` and `end`.
- `args`: `file --always`, `live --speaker` without the local engine and `live --source stdin --rate 0.001` are usage errors.
- `turn::features` against a stored reference vector (the README claims equality with transformers to 2e-6; the test in the tree checks only shape and range).
- `the_structs_match_the_header` passes without checking when no C compiler is found: make that a failure in CI.
