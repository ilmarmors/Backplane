## Summary
`ui.rs` is the window's `render`: top bar, sidebar part (projects, shelves, bots, rooms), timeline rows, rail, composer area and overlays. It also registers every control into an e2e inventory (`CtlEntry`). `keys.rs` holds the shortcut table, the bindings with their context expressions (pad and terminal mutes, Mac Cmd+Q) and the sidebar navigation helpers. `input.rs` is the GPUI example's single-line `TextInput`, used only for the three pairing fields (`screens/pair.rs`). The composer is a different widget, so the "very large paste" focus point belongs to `screens/composer.rs`. `script.rs` is the metrics contract and the scripted-input driver. It is switched on only by `--script FILE` or `BACKPLANE_GPUI_SCRIPT` at launch, nothing from the hub or the socket can start it, and the pairing relaunch strips the env var. So it is no remote-control surface, though it ships in release builds. The code is defensive about hub data: `Value` indexing everywhere, depth and count caps on hub nodes (`node_el` depth 14, 200 kids, 60 cards), and no unwraps on hub fields in these files. The main risks:
- A sidebar cat keeps repainting the sidebar at 30 fps for as long as a bot "needs you".
- The client-to-hub command queue is not drained while disconnected. Clicks made offline are replayed late, or dropped silently once the queue is full.
- `TextInput` has upstream IME and `assert_eq!` panic paths, and has no Cmd bindings on macOS.
- Prev/Next thread and Ctrl+digit follow `data.projects` order, not the hub's sections that are drawn.

## Improvements
| Priority | Area | Proposal | Why | Effort | Trade-off |
|---|---|---|---|---|---|
| P1 | Command channel | Give `Command` a "needs a live view" class. Discard such commands, or fold them into the session, when the session ends, and surface a `try_send` failure once ("not sent, reconnecting"). | Fixes stale replay and silent loss in one place instead of in about 240 call sites. | M | The hub thread must know which commands are idempotent (`Select`, `Draft`) and which are not. |
| P2 | Render cost | Build the `CtlEntry` inventory (ui.rs about 700-762, the sidebar's `ctl`, `rows_ctl`) only when `art::rects_on()` or a script is loaded. | Every frame of a normal session formats hundreds of id and label strings that only the e2e harness reads. | S | `do_click` and `ClickWithin` need the list when a script runs, so gate it on `steps` or `rects_on`. |
| P2 | Timeline | `resolve_by(\|id\| rows.iter().position(..))` runs up to three times per frame (ui.rs:516, 544, 924), scanning all entries for each registered id. Build an id-to-index map once per picture. | O(rows × ids) per frame on long threads. | S | A cache to invalidate on each picture. |
| P2 | TextInput | Replace the example-derived `input.rs` with the composer's editing core in single-line mode, or at least add the IME, boundary and Cmd fixes above plus tests. | One editor with one set of tested behaviours on both platforms. | M | The composer is heavier than a single-line field needs. |
| P3 | Script driver | Gate `script.rs` steps that touch files (`attach`, `files:upload`, `Expect`'s `exit(4)`) behind a check-mode env var as well as `--script`. | A release build runs any step file it is given, which keeps the shipped attack surface small. ## Missing tests
- `input.rs` has no tests at all. Add: a two-step IME composition (`replace_and_mark_text_in_range` twice, then commit), checking that the selection stays within the content; UTF-16/UTF-8 offset round-trips with emoji and CJK; `character_index_for_point` with empty content and in streamer mode.
- An idle-window test: with a bot whose mood is `wait` and no stream in flight, the window requests no further frames (covers the cat loop).
- `hub.rs`: commands sent while the session is down are not replayed after reconnect, or are reconciled, and a `Page` sent before `view.open` is answered does not end the session.
- `keys.rs`: no two `TABLE` entries can be rebound onto the same keystroke through `choices` and `Local::set`, and the Prev/Next order matches the drawn sections when `sections` is present.
- `keys.rs`: on a Mac keymap, `cmd-v`, `cmd-c`, `cmd-x` and `cmd-a` in the `TextInput` context reach `text_input::*` (currently they reach nothing).
- `script.rs`: `load` reports an unknown step and an unparsable file.

Does the hub's `reorder` handler refuse a move across projects or shelves? (ui.rs:198, value `"<dragged>\u{1f}<target>"`)
- `native/gpui/src/screens/glue.rs:137`: `scroll_note` writes a `GPUI_METRIC wheel` line to stderr on every wheel event (throttled to one per 400 ms) in normal use, not only under a script. Is stderr noise from release clients intended?
- `native/gpui/src/hub.rs:155`: should the 64-slot events channel back-pressure the socket reader? While the UI thread is slow, `events.send(..).await` in the frame branch also stops the command branch of the same `select!`.
