## Summary
The unit runs kicad-cli DRC/ERC in the background (`checkrun.rs`: scheduling, memory admission, systemd scope on Linux, remote runs over ssh, a JSON cache in `<home>/cache/checks`), turns reports into findings with ids stable across runs (`findings.rs`), keeps the old JS-ported review gate and checklist (`checks.rs`), folds review comments stored as `ActivityLogged` acts (`review.rs`), relays KiCad comments into threads (`comment.rs`), builds the design-history bar from step acts and git (`histsteps.rs`), keeps per-part stock and lifecycle history (`parthist.rs`, `lifepanel.rs`) and cross-probes between chat, viewers and KiCad (`xprobe.rs`). The pure parts are well tested and defensive (a failed run never reads as clean, cancelled runs keep the old result, kicad-cli is killed on drop and bounded at 600 s). The main risks are state contracts between pieces: the external sources' freshness check compares two differently built revision strings, so every design-review source reads stale while KiCad checks itself; every KiCad selection writes SettingSet events to the append-only log; the review gate in `checks.rs` ignores KiCad's `excluded` flag that `findings.rs` honours; review comments have no authorship rule for edit and drop, and their ids can collide. History reads pass every commit on one command line, which breaks on Windows for long histories. Several review helpers (`pins`, `moved`, `issue`, `md`, `label`, `say`) have no caller outside tests, so comment pins and anchor drift are not computed by the hub. The `gerber::DIFFS` queue is drained on every tick that has a live project and is deduplicated by set path, so it does not grow without bound.

## Missing tests
- With an editor that checks itself (revisions with `+e<n>`), an external source set just now reads `fresh` in `summary`, and a board-only project's source turns `stale` after a board save.
- Two consecutive identical `ET_SELECTION_CHANGED` events commit at most one `SettingSet` (after a fix).
- The `checks.rs` gate with an excluded error (`"severity":"error","excluded":true`) does not block; a report with an `info` severity item is valid.
- `review.comment` adds twice in the same second both survive `fold`; an agent `drop` of a person's comment is refused.
- `histsteps::have` with more than 1,000 commits (stdin path), so the Windows limit is covered.
- `set_findings` for two Gerber sets of one project keeps both.
- `lifecycle_of("Inactive")` and a BOM with more than 400 lines where an EOL part is beyond line 400.
- `parthist::append` from two threads at once loses no line.

## Cross-unit questions
- Reviewer question, answered: `gerber::DIFFS` (kicad/gerber/mod.rs:38) is drained with `mem::take` on each checks tick (checkrun.rs:440), but only when at least one project is live. With none live, `tick` returns at line 437 before the take, so the entries wait (60 s ticks) until a project becomes live. It is bounded: `plot` replaces the entry for the same set (mod.rs:67), so it holds at most one entry, with all its places, per distinct set compared since the last drain. Does anything cap the places per set? `gerber_findings` takes 2,000, but DIFFS keeps them all.
