## Answer to the other reviewer's question: is textgen's one-shot gated on a copy hub?
Yes, twice, and neither gate is in textgen.rs. `shot_r` (textgen.rs:142) calls `self.cli.resolve(provider)` unless `via.program` is set; `Cli::resolve` (agents/proc.rs:38) returns `Err("a copy of a log runs agents only as stand-ins")` when `BACKPLANE_COPY=1` and there is no stand-in dir. Whatever program is used, `proc::spawn` -> `spawn_with(Kind::Agent)` goes through `proc.rs` `refusal`, which on a copy refuses every `Kind::Agent` program outside the `BACKPLANE_AGENTS` folder (proc.rs:38, tested at proc.rs:154-157). So the named-account path (`via.program = launch_plan(...)`) is refused as well. A side-by-side hub (`person_turn_allowed`) still refuses it, because one-shots use `Kind::Agent`, not `PersonTurn`: titles, summaries and side answers are not written there. The background starters (iconpick.rs:74, groupname.rs:36) also return early on `copy::on()`. Residual: on a copy, `shot_healthy` still calls `mgr.launch_plan(...)` for each named account before the spawn is refused (textgen.rs:171); whether `launch_plan` touches the person's profile files is for the accounts unit (see questions).

## Summary
The unit assembles what agents are told (prompt.rs over generated literals, refs.rs, skill notes), finds the person's skills in every provider's folders for the `$` popup and the turn text (skills.rs), ships the bundled SendCutSend skill into the hub home (bundled.rs), and runs one-shot light-model calls for titles, summaries, handoffs, side answers, project icons and group names (textgen.rs, iconpick.rs, groupname.rs). Quality is good: the code is dense but careful, the copy gate holds, skills are never written into the person's folders by this unit (the only writer is `settings/skill_install.rs`, which refuses on a copy, caps the size, checks the folder name and does not overwrite without `replace`), the bundled install writes atomically into the hub's own home and sweeps only inside `<home>/bundled/skills`. Tool names the prompt tells agents to call all exist. The main risks are cost and privacy of the background one-shots: icons and group names ignore the Writing setting, a swallowed commit failure turns into a model call every 30 or 60 seconds, and a thread's content can cross to another Claude account when the thread's own account cannot answer. Test coverage of the pure parts is good; the async runners (`shot_healthy`, `retitle`, `icon_round`, `group_round`) have none.
