## Summary
Four GPUI screen files: the viewer pane (tab/page selection, Diff, Review, Split, plot chrome, pane sizing), the timeline text layer (Markdown blocks, selection registry, links, images), the multi-line composer element (shaping, caret, IME, paste) and the floating and in-chat terminal views. Quality is good for the density: the pure rules (pane fit, split shares, key bytes, card window, selection by identity) are in small functions with real tests, markdown depth is capped (md.rs MAX_DEPTH 16), image fetches are keyed so there is no repaint loop, link routing is a whitelist (http, https, mailto, hub, file). The main risks are in the terminal: the client answers the emulator's queries only for the panel, drops them silently otherwise, follows the open thread by starting a shell per thread visited, and sends every input chunk with a fire-and-forget `try_send`. A second cluster is state that lives in client statics and is not reset on reconnect (`WATCHED`). No panics on hub data were found on the traced paths. Tests cover pure helpers well but not the `Term::frame` card paths, the follow-the-thread behaviour or paste chunking.

## Findings
| Severity | Status | Location | Problem | Impact | Fix |
|---|---|---|---|---|---|
| Medium | Confirmed | native/gpui/src/screens/term.rs:198 | `Term::frame` always calls `s.vt.drain()` after collecting the emulator's replies, but returns them only when `key == self.key && self.open`. For every chat-terminal card (key `x:thread:id`, never the panel's key) and for a hidden panel the replies (cursor position, device attributes) are thrown away. The test `frames_draw_only_screens_it_holds...` asserts the hidden case and its comment says the replies are left "to whoever shows it", but they are already drained. | A program in a chat card that asks the terminal something (fish, many TUIs, anything that sends DSR/DA1) never gets an answer: it waits for its timeout or misbehaves; the card accepts keys, so the user sees a stuck program. | Answer for any screen that has a focused card or is on show (return replies per key and send them to that key), or do not drain while the replies cannot be delivered; fix the comment. |
| Medium | Confirmed | native/gpui/src/screens/term.rs:336 | `term_layout` runs every frame: when the panel is open and the selected thread differs from `screens.term.key`, it calls `term_show`, which sends `term.open` for the new thread. Merely selecting other threads with the panel open starts one hub shell per thread visited (the hub's `open_shell` starts a pty in that thread's folder). `term_show` also never sends the home size back for the previously popped-out card (only `term_hide` does), so that card's pty stays at the panel's size. | Silent process spawn per thread navigated (cost, stray shells in worktrees); a popped-out card keeps a wrong pty size after the panel moves on. | Follow the thread only for display and open the shell on the first keystroke or an explicit press; restore the old card's home size in `term_show`. |
| Medium | Confirmed | native/gpui/src/screens/term.rs:223 | `term_rpc` is `let _ = self.tx.try_send(...)`. `term_send` and `card_input` split a paste into 64 KB chunks and send each this way, with no check, retry or feedback (the command channel holds 256, hub.rs:155). Same pattern for every viewer action (`btn` viewer.rs:140, sheets, rv-tick, view-sheet, close). | With a large paste, or while the hub is slow, chunks are dropped: a bracketed paste can lose its end marker (shell left in paste mode) or run a truncated command. A dropped button press does nothing and says nothing. | Return a bool from `term_rpc`, stop sending the rest on the first failure and show a note; cap paste size; one helper for UI actions that surfaces a full or closed channel. |
| Medium | Possible | native/gpui/src/screens/term.rs:195 | In `Term::frame`, a new pid (e.g. card "Run again", `term.restart`) replaces the screen with `Vt::new(cols, rows)` from the PANEL's size (`self.size`), not the card's own size (`s.home`). Whether the hub also sends a `reset` snapshot after a restart was not traced. | If no reset follows, the restarted card is a 100x24 grid for a pty of the card's cols x rows: output wraps at the wrong width until the next snapshot (rejoin). | Use `s.home` for a card screen (`if s.home.0 > 0`), as `ensure_card` does. |
| Medium | Possible | native/gpui/src/screens/viewer.rs:873 | `WATCHED` (static) remembers the last mech key for which `kicad.watch` was sent and is cleared only when `open != "mech"`. `Event::Hello` (main.rs:161) resets terminals (`term_rejoin`) but not this. The hub's watch state is per client (net/rpc.rs `watching`). | After a reconnect with a Mech part still open, `watch_for(.., last)` returns None, the watch is never re-sent, and the part's model stops updating until the person leaves Mech and comes back. | Clear `WATCHED` in the Hello handler (or key it to a connection id). |
| Medium | Possible | native/gpui/src/screens/term.rs:358 | The terminal takes text only from `KeyDownEvent` (`key_char`), with no input handler: no IME composition, no dead keys, and a `key_char` of more than one scalar (`one()` returns None, e.g. a decomposed accent or an emoji sequence) is dropped silently. The app ships a Japanese catalog. | CJK input and some composed characters cannot be typed in the terminal; no error. | Register an `EntityInputHandler` for the panel and cards, or send the whole `key_char` string when it is not a single char. |
| Low | Possible | native/gpui/src/screens/composer.rs:176 | `paste` handles each clipboard entry: an `Image` entry emits `ComposerEvent::Image` and a `String` entry is also inserted as text. A clipboard with both (spreadsheet or browser copy) attaches an image and inserts text. File entries (Finder copy) are ignored (`_ => {}`); I did not check which entries the vendored gpui offers. | Unwanted attachment on a rich copy; pasted files do nothing. | Prefer the text entry when one exists; handle file paths as `ComposerEvent::Files`. |
| Low | Possible | native/gpui/src/screens/composer.rs:304 | `request_layout` and `prepaint` each shape every logical line of the whole text (`shape_rows`), and `sync` copies the whole text into a `SharedString` on each edit; nothing bounds the draft. | A paste of several MB makes every frame and keystroke slow (two full shapes per frame while it is visible); `MAX_LINES` limits only the drawn height. | Shape only the lines in the scrolled window, or cache rows per (text hash, width) and share them between layout and prepaint; cap pasted size. |
| Low | Possible | native/gpui/src/screens/timeline.rs:341 | `ParseCache` fingerprint is the entry's text hash plus `nodes.len()`; node contents are not hashed. If the hub changes nodes (e.g. link targets, code tokens) without changing the text or the node count, the cached blocks stay. When 400 entries are held the whole cache is cleared. | Stale rendering of an entry whose nodes changed in place; reparse burst when a long thread shows more than 400 entries over time. | Hash the serialised nodes (or an hub-sent revision) and evict least recently used. |
| Low | Possible | native/gpui/src/screens/viewer.rs:341 | The current sheet is found with `on_key.ends_with(&sh.file)` (also `split_sheets` line 506): a sheet file that is a suffix of another's path (`power.kicad_sch` vs `main_power.kicad_sch`) matches both. | Wrong sheet highlighted in the Sheets list. | Compare whole path components. |
| Low | Confirmed | native/gpui/src/screens/viewer.rs:252 | `diff_page` caps lines at `MAX_ROWS` (1000) but a file with no lines (binary, rename, mode change) does not use budget, so a diff of thousands of files builds that many header rows in one frame; each line's text is shaped unbounded (`whitespace_nowrap`), so one minified 1 MB line is shaped whole. | Low | Confirmed | native/gpui/src/screens/term.rs:110 | `selected_text` indexes columns by `char`, but the grid is by cell: wide (CJK) glyphs take two cells. Also it rebuilds `vt.lines()` for every row of the selection (`row_text`), and the selection is stored as absolute rows, which shift when the scrollback hits its 2048-row cap. | Wrong text copied with wide characters; quadratic work on a long selection; selection drifts under heavy output. | Map cells to chars with the emulator's width info; build lines once per call. |

## Cross-unit questions
- native/host/src/files/webimg.rs:`allowed` checks the host string, not the resolved address: does the fetch resolve DNS and refuse private addresses, and does it follow redirects to them? The client sends any README or message image URL there (timeline.rs:369).
- native/host/src/term/mod.rs:369 `term.input` caps at `MAX_INPUT` elements of a JSON number array (4 bytes per byte on the wire); is the hub's reply or its input queue bounded per client when 256 chunks arrive at once?
- Does the hub send a `reset` snapshot frame on `term.restart` (term/mod.rs:377), so the card's size is right after a new pid (term.rs:195)?
- Does the hub drop a client's `kicad.watch` when its socket closes (net/rpc.rs:150), which would make the missing `WATCHED` reset (viewer.rs:873) a real bug?
- screens/drafts.rs and unsent.rs: does a draft in the composer survive a reconnect or thread switch (not part of this unit's files)?

## Style nitpicks
- `btn` (viewer.rs:135) wraps the command in a `RefCell<Option>` and rebuilds a `Command` through a clone and a `Command::Page(String::new())` fallback; a plain `Command::Action(a, v)` captured by the closure would do.
- `term.rs` doc comment says Ctrl+Shift+C, but on macOS the bindings are Cmd+Shift; and a plain Cmd+V returns no bytes (`bytes_for` returns empty for `platform`).
- `SPLIT`, `SPLIT_BOX`, `WATCHED` mutexes use `.lock().unwrap()`; a panic elsewhere poisons them and every later frame panics.
- `Composer::tab` consumes Tab with no popup (no `cx.propagate()`), so focus cannot leave the box with Tab.
- Many `/* i18n-ok */` and "0.14" comments cite the removed Bend tree; they will age.
