## Summary
This unit is the presenter's data for the thread page: the viewer tabs and pages (Board, Schematic, 3D, Mech, Files, Review, Split, Gerbers) as pure functions over the session and State (`viewer.rs`), the to-do and subagent panels (`panels.rs`), the Add-project folder picker (`picker.rs`), the thread header keys and the model/effort/account picker (`keys.rs`), and the page window (`window.rs`). The code is dense but carefully tested against recorded JS-hub fixtures, and most edge cases (cut listings, loops, path escapes, Windows separators) have tests. The main risks are: a char-boundary panic in `window::fold_choice` on client-supplied text, a key mismatch between the page and its watch when a sheet is opened after a board pick, blocking disk walks on every presentation (Gerber set scan, Mech parts, Files listing, markdown render), a viewer tab set that never depends on the project kind (a mechanical-only folder still gets Board, Schematic and 3D), and hard-coded effort level and agent lists that go stale. The Mech "Renders" page described in `docs/mechanical.md` has no data behind it here (`shots` is always empty).

## Style nitpicks
- Several functions put whole bodies on one line (`view_action`, `page`), which makes the `kicad.watch` request construction hard to follow; the same JSON string template is repeated in six places.
- `keys.rs` `tools()` has `let _ = archived;` to ignore an argument that is no longer used; drop the parameter.
- `picker.rs` `names` returns `(Names, bool)` and `Listing` stores a `HashMap<String, &'static str>` of tags: a small enum would document the three values "KiCad", "git", "".
- The Ctrl+. hint is a literal in `keys.rs` (`"Stop the running turn · Ctrl+."`) while the client's binding is user-rebindable (native/gpui/src/keys.rs:78, `Rebind`); the tooltip can be wrong after a rebind.
- File names `keys.rs`, `picker.rs`, `window.rs` in `present/` do not say what they hold (thread keys and model picker, Add-project folder picker, history window).
