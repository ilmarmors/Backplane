## Summary
`sendcutsend` is a well-built, offline-testable helper: it only does GET requests for three public files, has no credentials, no order or upload capability and no retries, so the "paid order placed twice" and "credential leak" risks do not exist in this code. The "never order without the person" rule is prose only, but nothing in the scripts could place an order. The cache handling (TTL, ETag, atomic replace, validation before keeping a body, offline fallback) is careful. Weak spots are error handling at the command line (only `ScsError` is caught, so a bad file gives a Python traceback with exit status 1, the same code as "a rule failed"), untrusted third-party text fed to the agent, and a few small file-path details. `backplane-e2e` is the weak unit: it is not compiled into the hub and was never moved off the removed JS/Electron/web-client era. It names a `backplane-serve` binary, `web/`, `scripts/build.sh`, an Electron desktop app, `~/.backplane-bend` and port 3787, none of which exist; `hub.sh` passes `--web`, which the Rust hub rejects with exit 2, so `hub.sh start` cannot work when a `web/` folder exists, and the stories are written for a web page and Electron app that this tree no longer has. Where it does run, isolation is mostly sound (own home, HOME and XDG redirected, no tailscale, stand-in agents, dead order server, kills only a PID it recorded after checking its command line), but it breaks the project's port and temp-dir rules and its `stop` only works on Linux.
