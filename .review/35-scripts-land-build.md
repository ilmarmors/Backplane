## Summary
The unit is the path from a lane to `origin/main` (land.sh, the author hooks), the machine-wide build queue (cargo-q, lib-buildslot, flock slots), the Boat offload, the main builder, the janitor and the fresh/watch/watchdog loop that gets a build into the running app. The design is careful and its comments carry real incident history: flock with `-o` so no child keeps a slot, captured PIDs and `setsid` groups, atomic `rename` publishing, a dry-run default in the janitor. land.sh itself is sound: it rebases, tests the exact tree, pushes a plain fast-forward and only then moves local main. The weak spots are around it. The test-skip cache and the failure files are shared across lanes and keyed on the wrong thing, so a lane can make main's gate skip tests or erase main's failure. The Boat result path is not fail-closed: a failed read of the artifact list is treated as "no artifacts", the old local binary is then staged and published, and the sha256 check is computed by the same box it is meant to check. check-author.sh passes when `git log` itself fails. worktree-gc removes ignored files with a landed worktree. The watchdog finds the watcher with `pgrep -f`. Almost nothing here has a test (land.sh, check-author.sh, lib-boat.sh, boat-*.py, main-build.sh have none; worktree-gc has one in native/guard).
