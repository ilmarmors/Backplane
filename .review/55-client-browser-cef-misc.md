## Summary
These files cover the client's embedded Chromium (CEF), windowed or off screen, for the Browser tab, plus the fallback that shows the hub's JPEG frames. They also cover the shared browser toolbar, download saving, streamer mode (the text masker), the i18n catalog and its source scanner, the vector art, the perf overlay, the cached parts and the theme and scale helpers. The code is careful about CEF's threading: `Tab::with` drops its lock before calling CEF, callbacks touch only mutexes and wake a bounded channel, and macOS gets an external pump. Shutdown closes each browser through `Drop`. The main risks are the engine's security settings:
- the Chromium sandbox is off (`no_sandbox: true`) on every platform;
- the DevTools port is a plain loopback port with no authentication, and it reaches a persistent profile;
- cookies are stored under a fixed key (`password-store=basic`, `use-mock-keychain`);
- every download, including one a page script or an agent starts, goes straight into ~/Downloads without asking;
- popups are not limited.

Streamer mode is a good pure function with solid tests. As documented, it does not cover the browser page or images, and the docs on the browser are partly stale (they say there are no downloads or file dialogs). The i18n code is sound. The scanner exempts a whole line once `i18n-ok` or `GPUI_LOG` appears anywhere on it, and in a tree with one-line functions that hides a lot. Small points: `Engine::shutdown` is dead code, macOS wakes the main thread 30 times a second forever once a Browser tab has opened, and a few state vectors grow without bound.

## Missing tests
- A CEF download started without a user gesture (a script doing `a.click()` on a download link) is not saved silently, once a policy exists. Today there is no test of the auto-save policy at all, only of the naming.
- Two concurrent downloads with the same suggested name end up as two files (an `unique_path` race test).
- `on_before_popup` limit: a page opening 50 popups leaves the tab count bounded and the active tab unchanged.
- Two client processes with the default profile both get a working engine, or a clear message.
- The i18n scanner flags an un-catalogued literal on a line that also carries an unrelated `i18n-ok` or `GPUI_LOG` literal.
- Masker coverage: `sk_live_` (Stripe), `ya29.` (Google OAuth), JWTs (`eyJ...`) and non-ASCII names in different case (`to_ascii_lowercase` leaves "Ā" alone) are not masked today and are not tested.
