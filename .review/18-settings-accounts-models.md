## Summary
The unit holds the pure account rules (bindings, pins, finding an account by name), the hub side of accounts (the `accounts` request, the retire watch, the sign-in and renewal alerts), the rows the phones and Settings draw, the sync of Claude's long-lived tokens between the owner's machines, "sign in there" (a provider login run on another machine's pty and driven from here), the usage read from Anthropic's endpoint, and the model list detection. The pure parts are careful and well tested: tokens never enter a snapshot, an argument or a log, the curl request takes its token on stdin from a validated string, the screen sent back from a sign-in is redacted, every far request is refused on a copy, and every child goes through `proc.rs` with a time limit. The main risk is the channel: sync tokens (a one-year Claude subscription token that does not rotate) are pushed to every linked machine as plain JSON in an HMAC-signed curl POST that allows `http://`, on every change, to a new link at once and again every ten minutes; a key typed in "sign in there" goes the same way. So the answer to the home-move reviewer is yes, `push_to` and the periodic `announce` send tokens in clear on an `http://` link, safe only when that link runs inside the tailnet. The second risk is `signin.act`: any link counted as the owner's gets a login shell on this machine that no client sees and no event records. The sync life cycle has holes that the tests do not reach: a removal on a receiving machine comes back, a renewal on a machine that did not make the token is overwritten, and an abandoned "Make a sync token" leaves a dead account on every machine. The account inventory is written to the event log whole on every registry revision, which is at least every five minutes for each connected account. No provider credential can be pulled by another hub: tokens are only pushed by the machine that made them, and `signin.state` answers ids, labels, emails and states only. Tests cover parsers and pure rules; `serve`, `announce`, `act_here`, `act`, `holds` and the alert record's end have none in the crate.

- Two hubs: remove a synced account on the receiver while the maker is away, then bring the maker back: the account stays removed.
