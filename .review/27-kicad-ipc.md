## Summary
The unit is the hub's road to KiCad: a pure-Rust nng REQ client (nng.rs), a run-time protobuf codec that copies protobufjs (proto.rs), one worker per socket (kipc.rs), the actor and pure rules for at most two headless `kicad-cli api-server` processes (ipc.rs, kserve.rs), and the co-editing, save, reload, open and library-table helpers around the embedded GUI. The wire layer is careful: framing is bounded, every request has a time limit, a failed or timed-out request drops its connection, replies are matched by id, garbage from the peer cannot hang or exhaust the hub, and nothing signals a process. The weak part is the actor's bookkeeping around process lifetimes: a server's ready line, exit and handshake result are matched to a project only, never to the process that produced them, so an older process can stop or orphan a newer one. The hub never checks that a headless server's loaded document still matches the file on disk, which is the lost-update path the unit was asked about; the reload machinery covers only the embedded GUI. Two documented controls are not wired: the info key `kicad.ipc.servers` is never published and no client sends `kicad.retry`, so a failed server stays failed until the hub restarts. The codec still drops input silently in two cases (camelCase keys, unknown enum words) although the Nov 14 change set out to stop exactly that. `libtables.rs` does write the person's own global KiCad tables, from any hub home including test hubs, with its "already offered" record kept per hub home. Tests are good for the pure rules and the wire, thin for the actor (one happy path) and absent for eviction, retire, stale events and the save gate's inputs. The three docs of the unit describe the removed JavaScript tree in several places (write-target flags, a read allowlist, a managed library profile) that the Rust code does not have.
