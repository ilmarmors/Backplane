## Summary
The unit makes a person's own always-on hub on a Boat sandbox (account, sizes, an eight-step make run, status and cost, Resize, Restart, Delete), puts an authenticating door in front of a Boat that has only a public address, keeps a reverse long-poll link for a hub its peer cannot reach, and moves the "home" (uberbot, bots, rooms, hooks, mail, vault, APNs key, paired devices) between the person's machines by signed far requests. The careful parts are good: the provider key never reaches argv or a log, the Boat's release is checked against the signed manifest before the Boat runs it, the public door is default-deny, serves one request per connection and has a test that walks every registered route, far requests are refused on a copied log and every curl is `Kind::Net`. No name from a machine or project reaches a shell: the Boat's host and name are constants and build ids are checked. The main risk is partial failure of the home move, which is not transactional: a restart between the sender's retire and the receiver's finish leaves the home live nowhere (and the row says it stayed), and an undo whose `home.retire` does not arrive leaves it live on both, with nothing that reconciles later. The move also trusts the link's transport: on a plain http link the whole vault, hook secrets and the APNs key travel in clear. On the always-on side the run's state lives only in memory and three paths lose track of a Boat that has no auto-stop and bills (the saved id is cleared on any API error, the idempotency key is never reused, a half-made Boat is not drawn in Settings). The receiver's dedup marks lines as seen before they are written, the late pass of the carry leaks project events, and the move takes `alwayson.*` settings and the Boat account key along, so the Boat's hub ends up driving itself. Tests cover the pure functions, the door and the tunnel's happy paths; `move_to`, its undo, a restart mid-move and `make::run` against the stand-in Boat are not tested in the crate.

## Style nitpicks
- Test knobs live in production paths: `BACKPLANE_MOVE_PAUSE_MS` (homemove.rs:574), `BACKPLANE_ALWAYSON_BUILD`, `_SOURCE`, `_RELEASE`, `_ADOPT`, `BACKPLANE_BOAT_API`, `BACKPLANE_BOAT_WEB` (no check that an override is https).
- `let step = |s: &'static str| s;` (homemove.rs:581) does nothing; `let _ = (url, secret);` (tunnel.rs:212) hides two unused bindings.
- `super::super::alwayson::CHOICE_KEY` in other.rs:47 is `super::CHOICE_KEY`.
- `save` (mod.rs:84) ignores a failed commit and still updates the in-memory copy.
- `Boat::account` (boat.rs:105-107) reads a failed `GET /api-keys` as "may do everything", so a narrow key that lacks actions gets no warning.
- `under_systemd` (other.rs:13) reads `INVOCATION_ID`, which any process started from a systemd unit or timer inherits; a desktop hub started that way calls itself a server.
- The doc comment on `Keep` says "every 5 minutes" while `every_s` is 10 with a gate inside; the `St` fields `cost_at` and `account_at` double as "last check" markers.
- docs/ALWAYS-ON.md says the Tailscale key "goes to the Boat on stdin"; make.rs:311 writes it to a file through Boat's files API. The same doc gives `alwayson.boat` as `{id, name, size, created, network, url}`; the code also keeps `link`, `made`, `build`, `adopted`.
- `hours` (rows.rs:16) prints a million as "1000,000".
- tests.rs:159 builds its expected month start by a string replace of another date.
- The `else` branch of `build` (make.rs:200-222) is not indented under its brace.
- homemove.rs mixes five jobs in one file and names its far helpers `ask`, `far`, `far_move` with three slightly different error texts for the same failure.
