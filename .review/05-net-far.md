## Summary
This unit lets one owner's hubs mirror each other's threads (`/far/push`, `/far/log`, a per-link mirror outside the event log), ask each other for things (`/far/rpc`: a default-deny method list, viewers, files, tool calls), and hold a person's messages for a machine that is away. The protocol core is well made: pure state machines with named tests, idempotent batches, a mirror that never touches `events.jsonl`, explicit copy gates on the asking side, and admission that fails closed (signature, then "one of the owner's own": approved, not revoked, sync on, found). A linked machine that is not approved can do nothing here except `peer.address`, which checks approval itself; an approved machine can do everything (turns, a shell, any folder), by design and without scoping or an audit trail. The main defects are at the seams. The push state machine assumes every batch reaches every link's queue, but `outbox::run` skips links that are not "own" at that moment, so a mirror gets permanent silent holes after its machine was away. The transport (one `curl` per request, 1 MiB reply cap, 15 s total) contradicts sizes and durations the unit itself plans for (6 MiB viewer pulls, 24 MiB files, a log line "however big", a `/btw` that "may take a minute"). The held-message outbox treats every 4xx as a final refusal although the owning side answers 403 and 404 in known transient windows, and delivery is at-least-once with only an in-memory dedupe on the owner. Request signatures bind neither route nor direction. Start-up is all-or-nothing: one unreadable mirror file leaves the hub with no far lane at all. Tests cover the pure parts and the auth refusals well; `outbox::run`, the `files.get` handler, large replies, slow replies and every retry-classification case are untested.

## Cross-unit questions

## Style nitpicks
- far.rs:170-171: the `thread_shared(o, "")` branches can never be true for a real log; they read as live logic.
- far.rs:119: `Reminded` renames `thread` with `Id`, so an empty thread becomes `<link>~`; `BotSet` uses `Opt` for the same case.
- rpc.rs:36-42 and 88: the `Arc<std::sync::Mutex<std::collections::HashMap<..>>>` types are spelled out four times; a type alias exists only for `Watching`.
- farview.rs:15: `MAX_SUBS` is one pool for all links, so one machine's windows can use up another's.
