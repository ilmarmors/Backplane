## Summary
The unit holds the secret vault and its masks, the API keys file, `setting.set`, the telemetry choice and sender, the local diagnostics recorder, the issue report builder, the outbound alert webhook and a few small settings handlers (zones, model mentions, account bindings, desk alerts). The cryptography is sound: AES-256-GCM with a fresh 96-bit nonce from the OS for every seal, the name as associated data, a 32-byte OS-random key, a fail-closed open and a staged, fsynced write of vault.json. Telemetry is the best-tested part: the body is a strict allowlist, the kill switches and the copy guard hold, and nothing is sent before the disclosure was drawn (opt-out, as docs/telemetry.md says, not "asked" as the README says). The weak points are around the vault rather than in it: plaintext `secret_run` files survive a hub exit, the key file is not fsynced, a vault locked by a slow key store stays locked until restart, and the keychain entry is bound to the literal home path. Masking covers events, agent lines, launch arguments and MCP answers, but not live streamed text split across chunks, hand-written api.env lines, or credentials the hub keeps outside the vault. Several parts are ported only in shape: the diagnostics recorder is never fed, the webhook never carries the documented `reason` or error text, `zone.report` has no caller and stores no rule. `setting.set` is a five-entry denylist, so every hub-internal setting is client-writable. `webhook.rs` is the outbound notifier only; inbound webhooks are in the bots lane and were not in this unit. No Critical or High finding.

## Missing tests
- A hub that dies during a `secret_run` with `files`: after the next `open`, nothing is left under `secrets/run`.
- A value streamed in several chunks is absent from `live_snapshot()`, `live_frame()` and the delta frames (today a test asserts the opposite as a limit).
- api.env lines `A=v`, `A="v"`, `export A='v'`, `A='v' # note`: every name `names` lists has its value in `values` (a property test over both parsers).
- Setup Off, then Settings On through `telemetry.choice`: `may_send` is true afterwards; and `setting.set onboard.usage=on` alone does not re-enable.
- `vault.key` durability: a fault point for the key file's flush, and an empty `vault.key` with no items lets a new save through.
- A vault whose key store does not answer at start opens later without a restart; a home given with a trailing slash or through a symlink finds the same keychain entry.
- A thread created before `Bindings::seed` has finished, and a default set and a thread created in one writer batch, both freeze the default that is in the log.
- A `fail` alert with text reaches the webhook with that text and a reason; an address with `[` or `{` is posted once; a failed delivery is logged.
- `foo(&buf, &len)`, `&mut x` and `&amp;` in a message make no model reference.
- `zone.report` of a zone with no stored rule leaves a usable rule (or is refused).
- A running hub records at least one `hub.rpc` latency in `/debug/diagnostics.json` (would have shown that nothing calls `note`).
- `setting.set` of `machine.id`, `home.at`, `registry.index`, `tz.rule.X` and `alert.t1` is refused (once a rule exists).
- `secret_run` output over 64K characters with the value across the cut is masked; two threads asking for one secret name are both told when it is saved.
- Two `models.refresh` requests start one detection; two concurrent `api-add` requests keep both keys.

## Style nitpicks
- `webhook::seen_fail` treats 4058 as "absent": that is libuv's number from the JS hub; Rust reports 2 or 3 on Windows.
- mask.rs unwraps poisoned locks, while vault.rs and diagnostics.rs recover with `into_inner`; a poisoned mask lock would panic every commit.
- `telemetry_send::job` drops the result of `random` (`let _ =`); a failure would give every such install the same all-zero id.
- `vault.json.<pid>.tmp` and `api.env.<pid>.tmp` left by a crash are never removed.
- net/copy_outs.rs:4 says nothing calls `deliver` yet; alerts.rs does.
- docs/diagnostics-backend.md counts 52 keys (9 errors, 3 gauges); the code has 10 errors and 6 gauges.
- `tail_text` adds cut bytes and cut characters into one "characters cut" number.
- `run` names a secret file `var.to_lowercase()`, so `files {"KEY": a, "key": b}` share one file; `env_names` drops an invalid variable name without an error.
